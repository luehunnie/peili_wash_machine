现有站 + 预约增量

这不是一次改版：九页原型里，首页/抽屉/明细全部照抄现站（V1 清爽生活蓝），只在预约相关处做加法。视觉令牌零新增——新元素（药丸/角标/时段行/网格）全部由现站色对派生。

决策点 ① · 预约入口（三案递进，可单选可叠加）
入口 A抽屉内预约按钮 · 最小增量›

现有机器详情抽屉底部加一条操作栏「预约 · 选时段」，与既有信息区零冲突。页底附 A-2 备选（程序行内入口）。

改动最小先看价格再约入口藏一层
入口 C楼栋计数 + 机器卡角标 + 抽屉主按钮›

楼栋头「可预约 N 台」与「N 台 · 空闲 M」并列；可约机器卡右下角「可预约」角标（与楼层角标同族）；抽屉同 A。首页一眼可见哪些楼开了预约。

首页可见性A 的超集未开楼栋零改动
入口 D方案C 全部 + 全局入口横幅›

在 hero 与查询面板之间加「洗衣机预约上线了」横幅（去预约 / 我的预约单）。落位判断：现站无顶栏，横幅比顶栏更贴现站卡片语言；顶栏备选见页底 D-2。

C 的超集运营可下线全局可见
递进关系：A ⊂ C ⊂ D。A 保底可单独上线；C 补首页可见性；D 再补「不知从哪进」的全局动线。若担心首屏信息密度，可 C 起步、横幅等开学季再挂。
决策点 ② · 时段墙（二选一）
时段墙 A单机纵向时段列表›

日期页签（今天/明天/周四）+ 当日时段行：时间段 · 程序 · 价格 · 状态（可约/已满/已过）+ 选中态。行样式 = 现站明细 f-row 族，手机上信息密度最舒服。

逐台看适合单机楼默认推荐
时段墙 B全楼网格墙（行=时段 列=机器）›

楼栋 chips + 网格：一眼看全楼哪台哪个点空着。格子着色沿用三态令牌；≥6 列时格子偏小，单台楼建议自动回退成 A。

全局视野跨机器比价列多则挤
配套页 · 流程闭环（与入口/时段墙选择无关）
配套懒登录弹窗›

手机号 + 验证码（示例号 138 0013 8000 虚构）；三状态：初始 / 60s 重发倒计时 / 登录中。只在点「预约」时弹出，数据边界按 ADR-0001。
配套确认弹层 + 成功态›

机器/日期/时段/程序/价格五要素 + 免支付·确认即生效横幅；成功态 = 现站空闲灯语言放大。
配套我的预约单›

四状态（待生效/已生效/已完成/已取消，沿用官方 appointmentState 语义）+ 取消二次确认 + 空态。

阅读说明
纯静态无 JS：交互态用 :target（抽屉/弹层）与 :checked（页签/筛选/取消确认）模拟，页面链接可真实跳转；
样品数据虚构：机器名/楼栋名/价格沿用真实口径，时段占用与可约数量为虚构，每页角标注明；
视觉零新增：色/圆角/字号全部取自 src/style.css 令牌，深色模式只重定义令牌（同现站做法）；
画幅：手机 390px 竖屏（微信 webview）优先，桌面加宽不破格（弹层居中）。
