# M2 解冻预约：各自登录 + 仅免支付型，前端在本站

M1 冻结「无账号 / 零用户数据 / 只读」以隔离风险；2026-09-29 用户主动提出恢复预约（PROJECT_CONTROL_PACKET ESCALATE_WHEN 预定情形），且官方系统已对全校 22/58 台机器开启免支付预约（`reserveMethod=1`）。决定解冻，但边界收窄为：登录仅短信验证码、各同学用自己的账号（**共用账号方案否决**——平台代客执行交易的定性不可接受）；只做 `reserveMethod=1` 免支付预约，永不接触收银台；token 存同学自己设备的 localStorage（仅 `{token, 过期时间}`，手机号不落任何存储）；账号数据取用上限 = token + 我的预约单；写操作永不自动重试，失败提示「刷新后重试」。

## Consequences

- 「零用户数据」承诺精确化：「平台无服务器、不收集不转发任何用户数据；登录凭据仅存于你自己的设备，退出即删」。
- 与厂商的关系从「只读展示」升级为「第三方入口执行交易」，下架风险敞口变大——页脚与预约流程内双重免责（「预约由海乐生活系统执行，以现场为准」）。
- 技术可行性黑盒（时段表达、机器级预约单可读性、token 时长）由真实实验补齐后再出 SPEC-2；实验用用户本人账号，唯一一次真实下单须用户实时点头并备好取消。
